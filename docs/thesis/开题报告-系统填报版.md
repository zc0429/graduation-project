# 《毕业设计开题报告》学校系统六栏填报版

## 一、选题背景和意义

随着教育数字化和生成式人工智能技术的发展，学习平台已从资料存储与结果展示逐步转向学习过程支持。错题是学生学习过程中能够直接反映概念理解、解题方法和知识薄弱环节的重要材料，但传统错题本主要依赖手工摘录、分类和重复翻阅，整理成本较高，且常见问题包括知识点归类不统一、错因停留在答案对照层面、复习时间依靠个人经验、相似练习难以及时获取等。现有拍照搜题或题目收藏工具虽然能够缩短答案检索时间，却不一定围绕学生自己的错题形成持续的分析、练习和复习记录。大语言模型具备文本理解与生成能力，语义向量能够表示题目内容之间的关联，检索增强生成（RAG）可以把检索到的个人题库材料作为生成上下文，这些技术为构建面向个人错题的学习支持工具提供了新的实现条件[1-3]。与此同时，相关研究也指出，大语言模型在教育应用中仍可能出现事实性错误、解释不稳定和过度依赖等问题[2][11]，因此系统不能把模型输出视为无需核对的标准答案，而应通过限定知识点候选、引入个人题库检索、保留参考题标识以及用户确认等方式，使输出更便于核查和修正。

本课题拟设计并实现一个基于智谱GLM模型的AI错题分析与学习推荐系统，围绕“错题录入—AI分析—相似题与变式题练习—间隔复习—学习反馈”建立业务闭环。学生可通过文本录入错题，也可使用图片辅助识别，将识别内容回填后由用户确认再正式保存；系统采用智谱glm-4.7-flash完成知识点归类、错因分析、解题解析和变式题生成，采用embedding-3生成1024维题目语义向量，并结合个人错题库进行RAG检索。相似题推荐采用规则与语义检索结合的方式，复习计划采用参考遗忘规律的规则化间隔安排，练习结果用于更新题目掌握度，形成基于练习反馈的轻量知识状态跟踪。该研究的实践意义在于减少机械整理工作，为学生提供结构化的错题复盘入口、针对性练习和有节奏的复习提示；其研究意义在于探索大语言模型、RAG与传统Web系统在小规模个人学习场景中的组合方式，分析模型能力边界与工程约束；同时，课题覆盖需求分析、数据库设计、前后端开发、模型接入和系统测试，可检验本科阶段软件工程知识的综合运用能力。

本课题拟解决的主要问题是：如何把分散的个人错题转化为可分类、可检索和可复习的学习资料；如何在不训练BKT、DKT或认知诊断模型的前提下，根据练习反馈对知识状态进行轻量记录；如何利用同用户题库中的相关题目为大模型解析提供上下文，并以保守方式呈现模型结果；如何将相似题、变式题、复习计划和学习反馈连接成可运行的业务流程。预期形成一个功能边界清晰、数据归属明确、模型输出可供用户核查的Web系统，并通过功能测试与典型业务流程验证其可用性，为后续论文的设计、实现和测试章节提供事实依据。

## 二、文献综述

人工智能辅助学习研究经历了从规则式智能导师、学习者状态建模和资源推荐，到深度学习与大语言模型驱动的内容理解和生成等阶段。错题分析与学习推荐并不是单一算法问题，而是涉及题目语义表示、知识状态记录、复习时机安排、学习资源推荐以及生成内容核查的综合问题。为明确本课题的研究边界，本文从知识状态跟踪、间隔复习、习题推荐、RAG与大语言模型教育应用几个方面梳理相关研究，并结合国内错题资源和在线学习推荐研究进行评述。

在知识状态建模方面，Corbett和Anderson提出贝叶斯知识追踪（BKT），利用隐藏状态与作答观测估计学生对程序性知识的掌握情况[4]。该方法结构清晰、具有一定可解释性，但依赖知识点划分和概率参数设定。Piech等提出深度知识追踪（DKT），使用循环神经网络从连续作答记录中学习知识状态变化[5]，增强了对复杂序列关系的表示能力，但训练数据规模、结果解释和跨场景迁移仍会影响实际应用。Shen等对知识追踪模型、变体与应用进行了系统综述，指出数据稀疏、可解释性和真实教育场景落地仍是重要问题[6]。Wang等提出NeuralCD，以神经网络刻画学生、题目与知识概念之间的复杂交互，并强调诊断结果的可解释性[9]。这些研究为理解“知识状态”提供了理论基础，但BKT、DKT和NeuralCD均需要相应的数据、参数或训练过程。本课题面向个人错题本的小数据场景，不实现上述模型，也不宣称进行认知诊断，而是仅依据练习正确与否更新题目掌握度，并按知识点聚合当前状态，形成基于练习反馈的轻量知识状态跟踪。

在复习规律方面，Settles和Meeder提出可训练的间隔重复模型，利用学习者历史表现估计记忆半衰期并安排语言学习复习[7]；Nagatani等把遗忘行为纳入知识追踪研究，说明时间因素是描述学习过程不可忽视的变量[8]。相关工作表明，复习安排可以参考遗忘规律和历史反馈，但数据驱动模型需要足够的连续学习记录。考虑到本系统初期数据量有限，本课题不训练记忆预测模型，而采用固定复习节点形成规则化间隔复习计划。该方案的优点是逻辑清晰、实现成本可控，局限是尚不能针对不同学生拟合个体遗忘参数，因此论文中只将其表述为“参考遗忘规律”的工程规则。

在学习资源与习题推荐方面，Wu等将对比学习与强化学习用于个性化习题推荐，关注推荐准确性之外的长期学习收益[10]；董永峰等梳理了在线学习资源推荐中以知识点习题、学习路径、视频和课程为对象的多类算法，并指出学习者画像、行为数据与资源表示是常见依据[18]。韩姣等讨论了联邦学习在个性化学习资源推荐中的应用，强调跨平台数据利用与隐私保护问题[15]。这些研究展示了复杂推荐模型的潜力，但也意味着更高的数据量和训练成本。本课题的目标不是复现强化学习或联邦推荐算法，而是在个人错题范围内采用可解释的混合策略：先从同用户、同知识点题目中按难度接近程度排序，数量不足时再用语义向量检索结果补足。该策略更适合当前数据规模，也便于说明推荐依据，但其个性化程度主要来自个人题库范围、知识点和难度条件，不应被表述为掌握度驱动的自适应推荐。

在生成式人工智能与RAG方面，Transformer为大语言模型的上下文建模奠定了基础[1]。Lewis等提出的RAG框架将参数化生成模型与外部非参数记忆结合，使生成过程能够利用检索结果[3]；Gao等进一步总结了RAG的检索、生成与评估范式[13]。RAG可以为生成内容提供与任务相关的上下文，但检索结果本身的相关性、语料质量和提示组织仍会影响输出，因此不能把“采用RAG”等同于“消除幻觉”。本系统将RAG候选限制为同用户、同科目且排除源题，再按embedding-3生成的1024维向量计算语义相似度；RAG不强制候选与源题具有相同知识点，以免在知识点标注不完整时过度缩小候选范围。检索结果用于辅助glm-4.7-flash生成错因和解析，并保留参考题标识供页面展示，其作用是增加个人题库上下文和核查线索，而不是对答案正确性作绝对保证。

大语言模型教育应用研究普遍同时关注能力与风险。Kasneci等认为大语言模型可用于个性化辅导和反馈，但也讨论了错误信息、偏差及使用规范等挑战[2]；Yan等对相关研究进行范围综述，指出技术成熟度、透明性、隐私和以人为中心的设计需要共同考虑[11]；Chowdhury等将大语言模型与AutoTutor结合，通过教学策略和护栏约束导师系统行为[12]。Lo的快速综述同样显示，大模型在不同学科中的表现并不一致，教育应用需要配合核查和使用规范[14]。Team GLM介绍了ChatGLM系列模型的发展与中英文能力，为选择智谱GLM技术路线提供了模型背景资料[19]。上述研究提示本课题应把模型定位为学习辅助工具：文本分析与变式题使用真实glm-4.7-flash，图片辅助录入使用glm-5.3-flash，并通过“识别回填—用户确认—正式保存”避免把图片识别结果直接写成已确认错题。

国内关于错题资源利用的研究强调错题收集、分类、归因和针对性练习。孙辉以高中物理错题资源为对象，讨论了系统整理、专题讲解和练习应用[16]。唐颖川以及张鲁燕和巩清波分别从探究型课程和“双师课堂”等角度讨论大语言模型在教育中的使用路径[17][20]。这些研究说明国内教育场景正在积极吸收大模型技术，但部分成果更偏教学模式或应用讨论，对个人错题数据的持续管理、RAG上下文边界和复习反馈闭环涉及较少。

总体来看，现有研究已经为知识状态建模、遗忘因素、习题推荐和RAG提供了较丰富的方法，但直接采用重型模型并不适合所有小数据学习场景；大语言模型能够辅助分析和生成，却仍需面对输出不稳定与核查责任问题。由此，本课题选择“个人错题库+智谱GLM+语义检索+规则化复习+轻量反馈”的技术路线，重点研究各模块如何形成真实可运行的闭环，并明确不实现BKT、DKT、认知诊断或掌握度驱动推荐。其改进点不在于提出新的基础模型，而在于以较低复杂度整合已有方法，控制数据范围和功能边界，为个人错题复盘提供可实现、可验证的系统方案。

## 三、研究内容

本课题研究的核心问题是如何围绕学生个人错题建立连续的学习支持流程。研究首先对错题、科目、知识点、AI分析、变式题、复习计划、练习记录、消息和公告等业务对象进行划分，明确学生、教师和管理员三类角色的权限边界。学生负责维护自己的错题并使用分析、练习、复习和报告功能；教师查看系统现有的全站聚合学习统计；管理员维护用户状态、科目、两级知识点和公告等基础数据。数据库设计以当前真实业务实体和数据归属为依据。

错题录入支持文本方式和图片辅助方式。文本方式由学生填写科目、题干、答案和来源等信息；图片辅助方式调用glm-5.3-flash识别图片中可见的科目、题干、学生作答和来源，识别结果仅回填录入表单，经过用户确认后再走正式保存流程。错题保存后，系统调用glm-4.7-flash完成候选知识点范围内的知识点归类、难度评估、错因分析和解题解析，并调用embedding-3生成1024维题目语义向量。AI分析可引用个人题库中的RAG结果，页面展示相关参考题标识，便于用户结合原题核查；模型输出作为学习辅助内容，不表述为标准答案或准确性保证。

RAG与相似题推荐采用不同但关联的候选策略。RAG候选范围限定为同用户、同科目、排除源题且已有有效向量的错题，不强制同知识点，系统计算向量余弦相似度并选取排序靠前的题目作为生成上下文。相似题推荐采用混合策略，先在同用户、同知识点的候选中按与源题难度差值由小到大排序；若数量不足，再由上述RAG语义向量结果补足并去重。变式题由glm-4.7-flash根据原题、答案和知识点生成，供学生进行针对性练习。该路线强调个人数据边界、规则可解释性和语义补足，不将推荐描述为基于BKT、DKT、认知诊断或掌握度变化的自适应决策。

复习与反馈模块在错题创建后生成参考遗忘规律的规则化间隔复习计划，向学生展示到期或逾期任务，并记录完成情况。学生重做原错题或完成变式题后提交作答与正确性反馈，系统据此更新对应错题的当前掌握度，形成基于练习反馈的轻量知识状态跟踪。学情报告按请求实时聚合错题数量、本周新增、复习完成情况、当前平均掌握度、各知识点掌握度分布、薄弱知识点以及本周每日新增错题和练习量；学生查看本人数据，教师查看全站聚合数据，系统不建立历史报告档案。

系统采用前后端分离的Web架构，后端使用Spring Boot 3.5.16、MyBatis-Plus与MySQL 8，前端使用Vue 3、Vite、Element Plus和ECharts，模型能力通过智谱接口接入。研究工作包括需求与权限分析、业务流程和数据库设计、前后端功能实现、模型与RAG链路集成，以及单元测试、集成测试和典型业务流程验证。最终以系统能否完整支持“录入—分析—推荐与练习—复习—反馈”流程作为主要工程验证对象，不在开题报告中预写尚未完成或需另行人工评估的实验结论。

## 四、研究方法、研究思路

本课题采用文献研究、比较分析、系统分析与设计、原型实现和实验验证相结合的方法。文献研究主要通过OpenAlex、Crossref、arXiv等开放学术数据库与预印本平台，Google Scholar等学术搜索平台，以及IEEE Xplore、ACM Digital Library、ACL Anthology、NeurIPS、Springer、期刊官网和出版社官网检索文献，围绕知识追踪、间隔重复、习题推荐、RAG和大语言模型教育应用进行阅读、归纳与评述，并核对作者、题名、年份、卷期、页码和DOI等元数据。比较分析用于区分重型知识追踪或认知诊断模型与本课题轻量反馈方案的适用条件，比较纯语义检索与“知识点、难度规则优先+语义补足”方案的特点。系统分析与设计用于确定角色权限、业务对象、接口和数据关系；原型实现与实验验证用于检查模型结构化输出、语义检索、功能联动和业务流程是否符合设计预期，但不以少量样本结果推出普遍性结论。

研究步骤按照学校任务书安排展开。首先，收集并整理相关文献和学校规范，界定研究问题、功能边界与参考文献范围；其次，依据任务书和实际学习场景完成需求分析，梳理学生、教师、管理员三类角色以及“错题录入—AI分析—推荐与练习—复习—反馈”业务流程；再次，完成系统概要设计和详细设计，确定前后端架构、数据实体、接口、模型调用方式、RAG候选范围、混合推荐规则和复习规则；随后实现并联调各功能模块，使用glm-4.7-flash完成文本分析与变式题生成，使用embedding-3生成1024维向量，使用glm-5.3-flash完成图片辅助录入；之后开展单元测试、集成测试、权限与数据归属检查以及典型业务流程验证，记录模型输出的适用边界和系统缺陷；最后依据真实代码、测试记录和学校格式规范撰写、核对并完善毕业论文。

完成研究所需的硬件条件为能够运行Java、Node.js、MySQL和现代浏览器的个人计算机及稳定网络；软件条件包括JDK 21、Maven、Spring Boot 3.5.16、MyBatis-Plus、MySQL 8、Vue 3、Vite、Element Plus、ECharts、Git以及VS Code或IntelliJ IDEA等开发工具，并需要可按环境变量安全配置的智谱模型接口访问条件。知识条件包括Java与Web开发、关系数据库设计、前后端接口开发、提示词与结构化输出设计、语义向量与余弦相似度基础、软件测试和学术文献检索能力。研究过程中还需遵守个人学习数据最小化使用、模型输出人工核查、密钥不进入代码仓库和引用元数据可复核等基本要求。
