## 需求确认边界

1. 知识内容的共享范围、归属和存储方式尚未定；私人错题默认继续按现有权限隔离，不因“复用”开放其他用户数据。
2. 讲解匹配条件、重新生成条件、未练状态的判定范围、并发生成处理需形成设计决定；不把导师举例中的题数和复习次数固定下来。
3. 原题复习允许重做；“未练优先”用于持续拓展练习，不能直接将已做过的原错题永久排除。
4. 第三章和DFD是目标需求分析；后续详细设计必须分别交代当前10表方案和待确认的资源存储方案。未经需求确认，不实现新后端功能。

## 证据和质量边界

- 本轮执行的是文档、图形、源文件及保留性验证，没有调用真实模型，也没有重新执行后端或前端测试。
- 既有Mock、真实模型与历史批次不合并统计。Gate5的27题、6题RAG对照和人工CSV保留原始值与负结果；用户体验方案不能当作真人测试结果。
- 新需求验收至少检查“命中复用→缺少才生成→校验保存→记录具体题目→继续查库”完整链路，并将模型调用次数与数据库回读作为证据；以上是待执行验收场景，不是已通过测试。
