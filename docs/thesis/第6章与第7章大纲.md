#### 6.2.2 错题录入与错题本实现

#### 6.2.3 AI 解析与 RAG 推荐实现

- 说明 `LlmClient` 具备离线 `MockLlmClient` 与 OpenAI-compatible 实现；正式论文模型为智谱 `glm-4.7-flash`，向量模型为 `embedding-3`（1024 维）。DeepSeek 仅是早期兼容调用链路验证，不作为正式题目或最终效果证据。
- 引用 `docs/validation/live-glm-validation.md`：真实 Chat、Embedding、RAG、5 个结构化分析样本和 Variant 3/3 已验证；不将小样本验证外推为真实教学效果。
- 引用 `docs/validation/embedding-rebuild.md`：历史有效错题 3/3 重建为合法 1024 维向量，RAG 示例余弦相似度为 0.855025。
- 引用 `docs/validation/real-ai-e2e.md`：独立证据学生通过真实浏览器完成 GLM 分析、RAG 命中、3 道 Variant、练习与 mastery 更新，并形成 12 张 1600×1200 正式论文候选截图。
- 说明 AI 解析使用题干、可选答案、候选叶子知识点和参考题题干片段；系统没有独立持久化的 `studentAnswer` 字段，图像识别返回的学生作答只用于前端候选回填，不作为解析提示词的独立输入。
- 关键代码选取：`AiAnalysisServiceImpl`、`EmbeddingServiceImpl`、`RagServiceImpl`、`OpenAiCompatibleLlmClient`、`MockLlmClient`。

#### 6.2.4 相似题与变式题实现

- 说明相似题只在当前用户数据中选择：同知识点题按难度差优先，不足时由同用户、同科目向量检索补充，去重后最多 5 题；推荐逻辑不读取掌握度、练习记录或复习计划。
- 说明 RAG 候选限制为同用户、同科目、排除源题且向量非空，不对知识点硬过滤。
- 变式题同步请求模型并严格校验 3 道结果，输入快照防止并发编辑后旧结果落库。

#### 6.2.5 遗忘曲线复习计划实现

- 说明录入当天为第 0 天，系统按第 1、2、4、7、15 天建立五阶段复习计划。
- 本次两条自动化错题生成 10 条计划记录；同日“今日复习”为空是业务规则的真实结果，脚本未篡改计划日期。
- 说明计划不会按个人历史作答自适应改期；每日 08:00 标记过期计划并提醒当天任务。
- 说明练习目标强制为错题或变式题二选一，答对 +15、答错 -20，原子更新原题 `mastery` 并限制在 0–100。该规则分值不是 BKT/DKT/IRT 或掌握概率。

#### 6.2.6 学情报告与消息通知实现

- 说明报告在请求时聚合错题总量、本周新增、当前平均掌握度、本周复习总数/完成数、知识点平均掌握度、薄弱知识点、每日新增错题和每日练习次数。
- 学生按本人数据统计；教师和管理员看到系统范围聚合数据。教师没有班级、课程、学生绑定或明细下钻。
- `generate` 接口复用当前聚合结果并发送站内消息，不生成报告 ID、快照或历史记录；周一 09:00 定时任务仅发送“周报已更新”提示。
- 页面实际图表为每日新增错题柱状图和每日练习次数折线图，不写雷达图、掌握度历史趋势或未来日历。

### 6.4 系统业务流程实现

#### 6.4.1 错题分析闭环

- 错题录入 → 数据持久化与五阶段计划 → 前端另行触发异步解析 → Embedding 与 RAG 参考检索 → GLM 结构化生成 → 知识点/难度回填与解析展示；真实智谱浏览器证据已经留存。

#### 6.5.4 自动化与真实链路测试结果

- 冻结前最终回归：后端 70 项中 66 通过、4 个真实入口默认跳过；前端 typecheck、Vitest 23/23、生产构建、Mock Playwright 44/44、隔离库联调 4/4 通过。

- 向量维护：3/3 有效历史错题由旧 8 维向量重建为合法有限 1024 维向量；failed、stale、skipped 均为 0。
- 真实浏览器：独立证据学生完成 GLM 分析、RAG 命中、3 道 Variant 展示与数据库回读、练习后 mastery 由 0 更新为 15，生成 12 张 1600×1200 候选截图。
- 图像识别：真实 `glm-5.3-flash` 识别链路及禁用、格式、大小、科目匹配、人工确认和无副作用边界已验证。正式成稿引用对应 `docs/validation/` 文档，不暴露 API 密钥。

#### 6.5.5 Gate5 自动指标与人工评审状态

- 合成受控集共 27 题、3 个科目、9 个叶子知识点；知识点 Exact Match 为 26/27（96.30%）。
- 错因概念覆盖自动代理均值为 94.14%，中位数 100%，其中 22/27 达到全覆盖。该指标是字符串/概念覆盖代理，不等同于专家对错因质量的人工评分。
- RAG 指标为 Hit@3 0.962963、Recall@3 0.870370、MRR@3 0.864198；混合推荐为 Hit@5 1.000000、Recall@5 1.000000。
- RAG OFF/ON 小样本 A/B 的概念覆盖均为 88.89%，结构合规均为 6/6；ON 平均输出只多 20 个字符，不能据此声称 RAG 显著提升解析质量。
- 最终成功轮之前共有 34 次失败尝试：14 次 HTTP 429、15 次解析状态 2、5 次结构校验失败；如需讨论超时，只引用其他真实 GLM 验证记录，不把 Gate5 失败误报为超时。

## 7 总结

### 7.1 主要工作总结

- 总结完成 Spring Boot 3.5.16 + Vue 的前后端分离系统，实现三角色权限与 10 表数据模型。
- 总结错题录入、可配置模型解析、RAG 参考、混合规则相似题、3 道变式题、固定节点复习计划和请求时聚合报告组成的业务闭环。
- 总结后端/前端自动化、隔离库联调、真实智谱接口、向量重建、真实浏览器、图像识别和 Gate5 自动指标形成的证据链。

### 7.2 系统特点

- 将错题管理从单纯 CRUD 扩展为分析、推荐、复习和反馈闭环。
- 通过 `LlmClient` 接口隔离模型提供方，支持 Mock 离线演示、DeepSeek 临时联调以及智谱 GLM 正式接入。
- RAG 解析展示本地参考题关系，使解析来源比无依据生成更易追溯。
- 复习计划、练习记录、题目级规则掌握度与周报统计形成数据闭环；不将其表述为概率知识追踪。

### 7.3 存在的不足

- 智谱 GLM 与 Embedding 已完成真实验证，但样本仍为受控数据，Gate5 输入比正式 UI 提供更完整的学生错误信息，不能代表真实学生群体、长期学习过程或教学效果。
- Gate5 人工盲评表尚未填写，当前错因质量和 RAG A/B 仅有自动代理数据。
- 教师端当前为全科目聚合视角，尚无班级—学生绑定和分层干预能力。
- 系统没有班级/课程数据模型、报告持久化、概率知识追踪或自适应复习；相似题推荐不读取 mastery、练习或复习数据。
- 缺少正式压力测试和生产部署证据，应用内存向量检索的容量边界尚未测定。
- 前端生产包存在大体积 chunk 警告，首屏加载和按需拆包仍有优化空间。

### 7.4 后续展望

- 在保持 `LlmClient` 边界不变的前提下完善提示词版本、内容安全、可观测性和降级策略。
- 扩展更贴近正式 UI 输入分布且带人工标注的错题评测集，完成错因和 RAG A/B 盲评。
- 完善班级与课程关系、教师干预、长期掌握度追踪和更细粒度的知识追踪模型。
- 增加导出鉴权、接口自动化、性能和安全测试，并引入持续集成。
- 对 ECharts 和 Element Plus 进行按需加载与代码分包，降低生产包体积。
