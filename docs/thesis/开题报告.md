## 一、选题背景和意义

### （1）选题的依据和意义

**选题背景**

随着信息技术的飞快发展和教育信息化的持续推进，个性化学习已成为教育领域的重要发展方向。在日常学习中，错题是反映学生知识薄弱环节的最直接载体，对错题进行科学的整理与深度的分析，有助于学生精准定位知识漏洞、提升学习效率。然而，传统的错题整理方式普遍存在明显不足：学生手工摘抄错题费时费力，难以长期坚持；错因分析停留在表面，无法准确对应到具体知识点；复习安排依赖主观经验，缺乏科学遗忘规律的指导；同类题目难以举一反三，导致同一知识点的题目反复出错。目前市面上的错题类应用大多停留在"拍照搜题、收藏答案"的层面，缺少知识点自动归类、面向个人错题的针对性解析以及基于遗忘曲线的复习推送，无法形成完整的学习闭环。近年来，以 Transformer 架构为基础的大语言模型快速发展[1]，检索增强生成（RAG）、语义向量检索等技术逐渐成熟，为解决上述问题提供了新的技术途径。在此背景下，设计并实现一个 AI 错题分析与学习推荐系统，具有较强的现实针对性。

**选题意义**

从理论意义上看，本课题将检索增强生成技术应用于教育垂直场景的错题解析任务，通过本地题库检索约束大模型生成，探索降低大模型"幻觉"的工程化方法；同时将知识追踪、认知诊断与艾宾浩斯遗忘曲线相结合，构建"分析—推荐—复习—反馈"的学习闭环，是对个性化学习理论的一次具体实践。从实践意义上看，系统能够帮助学生摆脱手工整理错题的负担，获得针对性的错因解析与变式练习，按照科学的遗忘规律安排复习，实现减负增效、精准补漏；教师端可以查看班级学情报告，把握学生的共性薄弱知识点。从个人意义上看，本课题覆盖需求分析、系统设计、前后端开发、AI 能力集成与系统测试的完整软件工程过程，是对本科阶段专业学习的一次完整实践总结。

### （2）拟达到的目的

本课题拟通过系统的设计与实现，解决以下三个核心问题：一是错题知识点定位难的问题，利用大语言模型自动完成错题的知识点归类，构建两级知识点体系；二是错因解析获取难的问题，采用检索增强生成技术，基于本地题库检索结果约束解析生成，保证解析的准确性与可追溯性；三是复习无规划的问题，依据艾宾浩斯遗忘曲线自动生成复习任务，并结合相似题、变式题推荐实现举一反三，最终形成"录入—解析—推荐—复习—反馈"的个性化学习闭环。

## 二、文献综述

**前言**

错题分析与学习推荐涉及智能教育领域的多条研究脉络：对学生知识状态的建模（知识追踪与认知诊断）、对学习资源的分发（个性化习题推荐）、对记忆规律的利用（间隔重复与遗忘曲线），以及近两年大语言模型在教育场景的应用。下面分别从国外研究现状与国内研究现状两方面进行梳理。

**国外研究现状**

在学生知识状态建模方面，Corbett 和 Anderson 于 1995 年提出贝叶斯知识追踪（BKT），将学生的知识状态建模为隐马尔可夫过程中的二元变量，通过猜测概率与失误概率推断学生对知识点的掌握程度[4]。BKT 模型结构简单、可解释性强，但它假设知识点相互独立，难以刻画知识点之间的关联。2015 年，Piech 等人首次将循环神经网络引入知识追踪，提出深度知识追踪（DKT）模型，能够自动学习知识点间的潜在关联，预测效果显著优于传统方法[5]。Shen 等人 2024 年的综述系统梳理了知识追踪的模型体系、变体与应用场景，指出可解释性与冷启动仍是该领域的主要挑战[6]。上述研究证明了数据驱动的知识状态建模是可行的，但这类模型需要大量作答序列数据训练，对个人错题本这种小数据场景并不直接适用，这提示本系统应采用"规则化掌握度评估 + AI 分析"的轻量路线。

在记忆规律利用方面，Settles 和 Meeder 提出可训练的间隔重复模型（HLR），将半衰期回归引入语言学习，根据每个学习者的历史表现预测记忆衰减并安排复习时机[7]。Nagatani 等人进一步将遗忘行为显式地融入知识追踪模型，证明考虑遗忘因素能显著提升预测精度[8]。这两项工作为本系统的复习计划模块提供了直接的理论依据：复习时间点的安排应当基于遗忘规律而非固定周期。

在学习资源推荐与认知诊断方面，Wang 等人提出神经认知诊断模型（NeuralCD），用神经网络刻画学生与知识点之间的交互，可解释地输出学生对各知识点的掌握程度[9]。Wu 等人将对比学习与强化学习结合用于个性化习题推荐，在保证题目相关性的同时优化长期学习收益[10]。这些研究表明"诊断—推荐"的组合是个性化学习系统的通用范式，本系统的相似题推荐与掌握度评估沿用了这一范式，但在实现上以语义向量检索替代重型模型训练，更适合本科毕设的工程规模。

在大语言模型教育应用方面，Kasneci 等人系统讨论了大语言模型为教育带来的机遇与挑战，指出其在个性化辅导、自动反馈方面潜力巨大，但存在事实性错误等风险[2]。Yan 等人的范围综述进一步梳理了大语言模型教育应用中的实践与伦理问题[11]。Chowdhury 等人将大语言模型与 AutoTutor 导师系统结合，通过教学策略与护栏机制约束模型输出[12]。Lewis 等人提出的检索增强生成（RAG）方法通过引入外部知识检索显著提升了生成内容的事实准确性[3]，Gao 等人的综述总结了 RAG 的技术范式与评估方法[13]。这些工作共同说明：大语言模型直接用于教育场景存在"幻觉"风险，而 RAG 是当前最有效的缓解手段之一，这正是本系统 AI 解析模块采用 RAG 架构的直接依据。

**国内研究现状**

国内学者在错题资源利用方面已有较多探讨。孙辉以高中物理为例，研究了错题资源的分类整合方法，指出错题整理需要从"收集"走向"归因"[14]；刘畅针对初中数学提出了错题资源有效利用的实践路径，强调错题的定期重做与变式训练[15]。这些研究肯定了错题资源的学习价值，但停留在教学策略层面，缺少信息化、智能化的系统支撑，这正是本系统的切入点。

在个性化学习推荐方面，韩姣等人研究了基于联邦学习的个性化学习资源推荐系统，在保护数据隐私的前提下实现资源精准推送[16]。在大语言模型教育应用方面，郑伊彬和叶新东构建了中学生对大语言模型写作平台的接受度模型，分析了影响学生使用意愿的关键因素[17]；唐颖川以 Python 课程为例探讨了大语言模型赋能高职探究型教学的模式[18]；王丹颖研究了大语言模型垂直化训练技术及其在行业场景的应用[19]；张鲁燕和巩清波提出了大语言模型赋能高职"双师课堂"的路径[20]。在检索增强生成落地方面，居发礼等人面向专业课程构建了基于 RAG 的智能知识库，验证了"课程题库 + 大模型"架构在教学答疑中的可行性[21]。

**总结**

综上所述，国外在知识追踪、间隔重复、认知诊断与习题推荐方面起步较早，形成了较完整的理论体系，近两年大语言模型与 RAG 技术的教育应用研究也发展迅速；国内研究紧密跟随，在错题资源利用、个性化资源推荐与大语言模型教学应用方面均有成果。但现有研究仍存在明显不足：一是通用搜题工具重"搜"轻"析"，缺乏针对个人错题的系统性归因分析；二是错题整理、解析、推荐、复习各环节相互割裂，没有形成闭环；三是大模型直接生成解析存在幻觉风险，需要检索增强等约束机制。本系统以"个人错题"为核心数据资产，将 AI 知识点归类、RAG 解析、相似题/变式题推荐与遗忘曲线复习整合为完整业务流程，正是针对上述不足的具体改进。

## 三、研究内容

### 1、通过本系统，我将研究以下问题的解决和实现

- （1）研究错题知识点自动定位问题：研究基于大语言模型的错题知识点自动归类方法，构建一级章节、二级考点的两级知识点体系，解决错题归类难、错因定位不准的问题。
- （2）研究解析质量问题：研究基于检索增强生成（RAG）的错题解析生成方法，以本地题库检索结果约束大模型输出，降低幻觉，保证解析准确且来源可追溯。
- （3）研究个性化复习问题：研究基于艾宾浩斯遗忘曲线的复习计划生成算法，以及基于题目语义向量检索的相似题推荐、基于原题的 AI 变式题生成方法，解决复习无规划、同类题反复错的问题。
- （4）研究多角色权限问题：研究学生、教师、管理员三类角色的权限划分与数据隔离，保证系统安全可用。

### 2、研究系统以下功能的实现

本次研究的目标是设计并实现一个基于 Spring Boot+Vue 的 AI 错题分析与学习推荐系统，具体实现包括以下 13 项功能：

1. **用户管理功能**：实现用户的注册、登录、信息修改、注销账号等功能，支持学生、教师、管理员多角色权限管理。
2. **科目管理功能**：用于维护系统涉及的学科信息，如数学、物理、英语等。
3. **知识点管理功能**：用于维护一级章节与二级考点的两级知识点体系，为错题归类提供基础。
4. **错题录入管理功能**：支持学生以文本或图片方式录入错题，维护错题的题干、答案、所属科目等信息。
5. **AI 解析管理功能**：系统调用大语言模型，结合本地题库检索增强生成（RAG），自动完成错题的知识点归类、错因分析与解析生成，并标注所参考的本地题目来源。
6. **相似题推荐管理功能**：基于题目语义向量检索，为学生推荐同知识点的相似题目，实现举一反三。
7. **变式题管理功能**：基于原题由 AI 生成变式练习，帮助学生针对性巩固薄弱知识点。
8. **复习计划管理功能**：依据艾宾浩斯遗忘曲线自动生成复习任务，并向学生推送复习提醒。
9. **练习记录管理功能**：记录学生重做错题与完成变式练习的作答情况，动态更新各知识点掌握度。
10. **学情报告管理功能**：定期生成学情周报，可视化展示薄弱知识点分布与掌握度变化趋势。
11. **错题本导出管理功能**：支持按科目、知识点筛选导出错题本，便于线下打印复习。
12. **消息通知管理功能**：用于系统向学生发送复习提醒、报告生成等通知消息。
13. **公告管理功能**：用于管理员创建公告信息，确保用户及时获取重要通知。

### 3、数据库设计（8 张表）

系统数据库共设计 8 张表：`user`（用户）、`subject`（科目）、`knowledge_point`（知识点）、`question`（错题）、`ai_analysis`（AI 解析记录）、`variant_question`（变式题）、`review_plan`（复习计划）、`practice_record`（练习记录）。

业务流程闭环：学生录入错题 → AI 解析并归类知识点 → 推荐相似题、生成变式题 → 按遗忘曲线生成复习计划 → 学生重做与练习反馈更新掌握度 → 生成学情报告。

## 四、研究方法、研究思路

**研究方法**

本系统会采用多种研究方法。首先运用文献法，通过知网、万方等平台查阅智能教育、知识追踪、个性化学习推荐、检索增强生成等方向的国内外文献，了解研究现状与发展趋势，为系统设计提供理论依据；同时使用实验法，在系统开发过程中重点攻克 AI 输出结构化控制、相似题检索效果、RAG 解析质量等技术难点，积累全栈开发与 AI 工程化经验；另外借助比较法，对比作业帮、小猿搜题等现有错题类工具的优缺点，明确本系统"重分析、成闭环"的差异化定位；最后使用问卷调查法，依托在校学生资源，调查学生的错题整理习惯与功能需求，为需求分析提供数据支撑。

**研究步骤**

在研究步骤上，首先收集相关文献，提取关键信息，对目标系统进行初步分析；接着围绕选题开展用户需求调研，了解学生在错题整理、错因分析与复习规划方面的具体需求；然后制定系统需求分析文档，明确要实现的功能，并设计技术方案，确定使用的框架、前端技术和数据库；之后进行系统设计（概要设计与详细设计）并编写程序代码，逐步实现各个功能模块；再进行系统运行测试，验证功能是否正常，并撰写测试报告；最后维护系统，确保稳定性与可靠性，修正问题，总结并完成论文撰写。

**所需条件**

所需条件方面，软硬件上需要 IntelliJ IDEA 用于后端代码开发，VS Code 用于前端开发，MySQL 用于存储数据，Git 用于版本控制，以及 Windows 开发机一台。技术上使用 Spring Boot 3 与 MyBatis-Plus 构建后端，Vue 3、Vite 与 Element Plus 构建前端，AI 能力通过大语言模型 API（如 DeepSeek、通义千问）与 Embedding 向量检索实现。知识上要掌握 Java 与 Web 开发、数据库设计、提示词工程、软件测试等知识。
