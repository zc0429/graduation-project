## 业务边界

1. 图片识别只回填候选，失败可手录；学生确认前不写错题、图片或复习计划。学生作答临时显示，不自动作为标准答案。
2. 平台保存错题时建立第1、2、4、7、15天计划，再独立请求解析；AI失败不撤销错题与计划，缺密钥时明确失败。
3. AI服务提供模型能力：GLM负责图像提取、辅助归类、错因与解题解析、变式生成，向量由embedding-3生成。平台负责过滤、检索范围、余弦排序、请求编排、状态和数据写入；AI不直连数据库。
4. 解析在本人同科目题库检索最多3个参考题；相似题推荐可按知识点和难度优先并以向量补足，最多5题。变式由模型生成3题，经平台整体验证后保存。
5. 练习由学生自评，正确加15、错误减20、范围0—100，记录与原题分值在一次事务中保存。
6. 复习图以一次查看和任务处理为单位，可再次进入列表处理下一项。每天08:00提醒当天待复习任务；逾期任务保留，练习不自动确认完成，不重排日期。
7. 管理和教师查看是两段独立业务。管理员操作按需选择，教师仅看系统聚合，无班级、逐题批改或学生个人钻取。

## 简短讲解稿

**图01**：“学生自己录入，或让GLM从图片提取候选。内容要先核对，识别失败就手录。平台保存题目并安排五次复习，再单独请求分析。检索和存数据库由平台负责，GLM辅助分析和生成。学生选择原题、已有相似题或新变式，练习后自己判断对错，平台记录并更新分值。”

**图02**：“复习计划在保存错题时就建立，不依赖AI成功。学生从提醒或列表查看到期、逾期任务，复习后单独确认。做过练习不代表完成复习；没确认就保留，日期也不自动改变。”

**图03**：“管理员维护基础资料和公告，教师查看系统汇总。这是两段独立业务，不要求每次学生学习都经过管理员或教师，也没有当前不存在的班级、学生钻取和批改。”
