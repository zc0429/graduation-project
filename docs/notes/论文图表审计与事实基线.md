## 一、项目事实基线

| 项目 | 核实结果 | 仓库依据 |
|---|---|---|
| 角色 | student、teacher、admin；注册只创建学生；JWT 后重新查数据库角色和状态 | `AuthServiceImpl`、`AuthInterceptor`、各 Controller 的 `RequireRole` |
| 学生 | 本人错题、图片、解析、RAG、相似题、变式题、练习、复习、报告和导出 | `QuestionController`、`AiController`、`PracticeController` 等及各 Service 归属检查 |
| 教师 | 系统级聚合报告、本人资料和消息、公告；无班级绑定与学生明细 | `ReportController`、`ReportServiceImpl`、`ReportView.vue` |
| 管理员 | 用户查询与停用、科目、知识点、公告发布；没有学生业务接口特权 | Controller 角色注解；Service 内部遗留 admin 分支不等于开放入口 |
| 功能口径 | 13 项需求按职责归纳为 8 组实现模块；不是 13 个独立服务或页面 | 正文表 3.1、表 4.1，后端 Service、前端路由 |
| 数据模型 | 10 张表、80 个字段；无物理外键；无班级表、课程表、报告表或独立向量表 | [schema.sql](../../server/src/main/resources/db/schema.sql) |
| 接口 | 36 个 HTTP 方法和路径映射；3 公开、33 鉴权 | [控制器目录](../../server/src/main/java/com/example/wrongbook/controller)、`WebConfig`；逐项见机器基线与表 5.11 |
| 页面 | 14 个正常路由页面组件 + 1 个 404 组件；旧“13 页面”是历史统计 | [router/index.ts](../../web/src/router/index.ts)、`web/src/views/` |
| 页面细目 | 登录、工作台、录入、错题本、详情、练习历史、复习、报告、消息、公告、个人中心、用户管理、科目管理、知识点管理 | 当前路由懒加载目标；同一页面可按角色呈现不同内容，不重复计数 |
| 错题保存 | 同一事务保存题目和 5 条计划；前端取得 ID 后另行触发 AI | `QuestionServiceImpl.create`、`QuestionCreateView.vue` |
| AI 解析 | 本地 Executor；状态 0 生成中、1 成功、2 失败；精确 4 字段校验；输入快照条件回写 | `AiAnalysisServiceImpl`、`useAiAnalysisPolling.ts` |
| 模型 | 正式文本 glm-4.7-flash、embedding-3 的 1024 维；图像为独立且默认关闭的 glm-5.3-flash | 客户端配置、三类真实验证记录；本轮未联网调用 |
| RAG | 同用户、同科目、排除原题、向量非空；二次归属检查；正余弦降序 top 3 | `RagServiceImpl.retrieveSimilar`、`AiAnalysisServiceImpl.doAnalyze` |
| RAG 输入 | 题干、可选答案、科目下 parent_id 非 0 的知识点、各参考题前 50 字符；无独立持久化学生作答 | `AiAnalysisServiceImpl.buildPrompt`；两级知识点约定 |
| 相似题 | 同用户同知识点、难度差优先；不足时同用户同科目 RAG 补足；去重后最多 5 题 | `RecommendServiceImpl`；不读取 mastery、练习和复习数据 |
| 变式题 | 同步生成；每次严格 3 道；校验后短事务锁原题、比较快照、整体保存；可多次生成 | `VariantServiceImpl.generate`；不能把数据库关系画成“原题最多 3 个变式” |
| 练习 | 原题/变式二选一；学生自评；同事务保存作答并更新原题 mastery，+15/-20，范围 0–100 | `PracticeServiceImpl`、`QuestionDetailView.vue`；无自动判分 |
| 复习 | 保存时第 1/2/4/7/15 天；每日 08:00 标记逾期并提醒当天待办；过期仍可完成 | `ReviewPlanServiceImpl`、`ScheduleTask`；完成不自动提交练习 |
| 报告 | 请求时聚合；学生本人、教师全系统；generate 额外发消息；周一 09:00 仅发查看提醒 | `ReportServiceImpl`、`ScheduleTask`；无报告快照 |
| 图片 | 识别只返回候选，不自动写业务表；保存题图与识别为不同步骤；私有题图经本人详情返回 | `QuestionRecognitionServiceImpl`、`QuestionServiceImpl`、真实图片验证 |

关系解释：`ai_analysis.question_id` 有唯一约束，因此错题与解析为 1:0..1；`practice_record.question_id` 与 `variant_id` 在数据库中均可空，但服务层强制二选一。删除或使题目失效后可能清理变式题而保留历史练习，故逻辑关系不表示历史引用永远可解析。`reference_ids` 是 JSON ID 留痕，不存在独立引用关系物理表。`knowledge_point.parent_id=0` 是根节点哨兵，不指向一条 ID 为 0 的真实记录。

本轮从 Schema、代码和既有验证确认以上内容，**未连接当前运行中的数据库**。不将仓库结构等同于某个现场数据库实例已完成迁移。需要现场答辩时复核实例 Schema、运行配置和演示账号，这是独立 TODO。
