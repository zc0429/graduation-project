## 失败及排除说明

- backend-first-build-failure.log：当前JDK缺少ct.sym/release元数据，Java21的source/target后编译成功，未改变工程语言级别。
- typesetting-install.log、backend-first-disk-failure.log、backend-baseline-runtime.log：本轮Docker vfs排版镜像与MySQL同时占满磁盘；首次测试尚未产生可用结果，首次后端启动失败。仅移除本轮可重建排版镜像后，基线完整重跑通过；应用验证完停止并移除临时MySQL后再安装排版工具，复现不需二者同时占盘。
- backend-first-integrity-regression-failure.log：113项中旧编辑集成测试1失败/5错误，因原夹具使用不存在科目；新增7项通过。补齐真实科目夹具、保留全部原断言后完整113项重跑通过，失败数不隐去。
- browser-ui-cancelled-to-protect-originals.log：发现默认包含一个历史截图生成用例，在执行到该用例之前主动中止；全部原件哈希未变。随后明确排除该用例，完整53项通过；不把中止轮计为成功轮。
- browser-supplement-first-no-fixture.log：首次补充执行缺少夹具，未形成有效界面验证；browser-supplement-first-port-failure.json/log记录4176端口不在既有CORS允许来源内导致登录未完成。改用已允许4175并建立明确夹具后，四流程完整通过，未放宽应用CORS。

运行日志末尾的主动关闭不等于测试失败；本轮曾用临时子进程启动应用，补充阶段确认旧进程不在后，以持久执行会话启动已打包JAR。最终实际执行证据以对应完整批次日志及JSON为准，不宣称每个临时进程始终在线。

## 可复现命令

先`npm ci`，按server配置启动专用MySQL，分别建立wrongbook_test和wrongbook_browser并执行现有DDL/种子数据；禁止将下列审计探针指向生产。`.local/mysql.env`只在本机保存随机临时MYSQL_ROOT_PASSWORD，不提交。设置TEST_DB_PASSWORD、TEST_DB_USERNAME、TEST_DB_URL，浏览器后端用DB_PASSWORD、DB_USERNAME、DB_URL并显式LLM_PROVIDER=mock、IMAGE_RECOGNITION_ENABLED=false，监听127.0.0.1:8080，上传目录用独立路径。

```sh
# 完整JDK可省略compiler参数；本环境使用相同Java21的source/target。
./server/mvnw -B -ntp -s .local/maven-settings.xml -f server/pom.xml \
  -Dmaven.compiler.release= -Dmaven.compiler.source=21 -Dmaven.compiler.target=21 test package
cd web
npm run test:unit -- --maxWorkers=2
npm run typecheck
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium \
  THESIS_EVIDENCE_DIR=../docs/validation/thesis-system-consistency-20261113/screenshots npm run e2e:integration
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium \
  npm run e2e:smoke -- --grep-invert '并生成本轮界面证据'
cd ..
.local/audit-venv/bin/python scripts/validation/probe_consistency_defects.py --phase after
.local/audit-venv/bin/python scripts/validation/verify_consistency_runtime.py
.local/audit-venv/bin/python scripts/validation/capture_consistency_schema.py
.local/audit-venv/bin/python scripts/validation/audit_thesis_system.py
```

Python依赖为现有文档工具依赖加pymysql。Maven代理配置只存在被忽略的.local目录；它不是凭据。probe脚本的`before`模式仅用于原基线复现，不能在修复分支上伪造修改前结果。独立目录已保留真实原轮结果，再执行这些命令会重写本审计目录，复验应复制工作区或先另存证据。

补充浏览器脚本`verify_consistency_browser.mjs`使用真实4175前端及8080后端。其.local/browser-fixture.json必须来自新建的审计原题和该题一条明确置为今日的复习任务（包含questionId、planId、stem、suffix），不得改历史实验日期；脚本把实际新建科目/公告ID写入browser-supplement.json供专用库回读与清理。本轮已回读mastery=15、该任务status=1/finish_time存在、原题作答1条，然后清理本轮夹具并停止临时服务。脚本不含模型密钥。
