## 最小部署安全收口

新增 `deploy-test` profile，并规定：

- 服务只监听 `127.0.0.1`，默认端口为 8081；
- 数据库 URL、账号、密码、JWT 密钥、上传目录和 CORS 来源必须显式注入；
- `spring.sql.init.mode=never`，不自动执行 `schema.sql` 或 `data.sql`；
- Mock AI 固定启用，真实模型与图片识别关闭；
- MyBatis SQL 详细日志关闭。

CORS 从“允许凭据并接受任意来源”改为精确来源白名单，仅允许系统实际使用的 HTTP 方法和请求头，并暴露 Excel 下载所需的 `Content-Disposition`。启动时拒绝空白名单和 `*`。

前端 Vite 开发/预览代理增加 `VITE_BACKEND_PROXY_TARGET`，未设置时仍使用原有 `http://localhost:8080`，测试部署时显式指向 `http://127.0.0.1:8081`。

本轮未启动或复用日常开发 `MySQL80/3306`。部署测试使用另一套独立实例：

- MySQL 数据目录：`D:\Dev\mysql-test\wrongbook-deploy-test-20260907\data`

- 部署库：`wrongbook_deploy_test`
- 回归库：`wrongbook_regression`
- 两个随机账号分别只拥有各自 schema 权限，没有全局权限

数据库密码、JWT 密钥和测试学生密码均在运行时随机生成，未写入仓库、日志或文档。验证结束后 root 凭据改为未保存的一次性随机值；应用和 MySQL 均已停止，没有端口监听。由于主机策略不允许递归删除临时目录，数据目录和 1 个测试图片文件仍保留，但没有注册服务或可复用凭据，不会自动启动。

- 图片文件仍在外置上传目录中，详情可正常读取。

随后以生产构建启动仅绑定 `127.0.0.1:4175` 的 Vite 预览，后端仍只绑定 `127.0.0.1:8081`。通过前端同源 `/api` 代理再次验证健康检查、旧 JWT、题目和图片，全部通过。

额外验证：不提供部署测试必填环境变量时，应用以退出码 1 启动失败，没有回退到 `dev` 数据库配置。

## 异常说明

正式回归和部署验证均无业务失败。准备阶段出现两项基础设施操作异常：

1. 首次初始化命令中的 PowerShell 内联路径表达式被原生命令错误解析；MySQL 因目标目录非空主动中止，未写入安装目录。改为预先解析的字面量路径后成功。
2. 首个包含后台进程停止逻辑的一次性编排命令被主机策略拒绝，整条命令未执行。改为可审计的分阶段前台会话后完成验证。

两项均发生在正式部署验证之前，不是系统缺陷，也未影响开发数据。

## 当前结论与后续边界

非公网测试部署所需的配置隔离、CORS、稳定 JWT、演示账号隔离、上传持久化和前后端同源代理均已验证。当前没有新的业务阻断缺陷。

系统冻结前仍应在项目约定的 Node.js 22 环境复跑前端验证，并决定是否为正式部署引入反向代理、TLS、数据库迁移和进程托管；这些不在本轮非公网测试部署范围内。小规模用户体验测试暂不启动。
