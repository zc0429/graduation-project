# 小规模用户体验测试方案

## 1. 当前状态与边界

- 方案日期：2026-09-07。
- 本文件只用于测试准备，不表示用户体验测试已经实施，也不包含参与者、评分、问题或结论。
- 测试目标是发现系统的可用性与业务流程阻碍，不评价学习效果，不将小样本结果外推为普遍结论。
- Gate5 已正式结束，不重新运行、不修改其人工评价或实验结果。
- 测试使用非公网 `deploy-test` 环境、独立 MySQL 实例与独立 `wrongbook_ux` schema；不得复用日常开发数据库。
- AI 固定使用 Mock，关闭 Gate5、真实 GLM、图片识别、Embedding 重建及其他联网模型入口。
- 参与者在同一台测试设备上分时完成任务；测试环境仅监听本机地址，不进入公网部署。

## 2. 开始前技术基线

2026-09-07 已在 Node.js 22.23.1、npm 10.9.8 下执行 `web/npm run verify`：

- TypeScript/Vue 类型检查通过；
- Vitest 8 个文件、23 项测试全部通过；
- Vite 生产构建通过；
- Playwright 四档视口 44 项冒烟测试全部通过；
- 构建仅保留主入口压缩后约 773.61 kB 的包体积警告，当前不阻断功能测试，记录为部署前性能观察项。

开始体验测试前，还应确认后端完整回归仍为 69 通过、0 失败、0 错误、4 个真实入口按预期跳过，并按 `docs/validation/deploy-test-validation.md` 的方式完成一次本机部署冒烟。

## 3. 参与者与会话安排

- 建议 5 人：3 名目标学生、1 名教师角色体验者、1 名管理员角色体验者。
- 每人单独完成一次 20—30 分钟会话；主持人只在参与者明确卡住时提供统一提示。
- 仅使用匿名代号（如 `P01`），不记录姓名、学号、班级、成绩、联系方式等个人敏感信息。
- 会话开始前说明测试对象是系统而非参与者；参与者可随时退出，退出不产生任何不利影响。
- 不录音、不录像；如确需截图，只截系统界面并避开账号密码、令牌和个人信息。

## 4. 固定任务

| 编号 | 角色 | 任务 | 成功标准 |
|---|---|---|---|
| S1 | 学生 | 注册测试账号、登录并进入工作台 | 无主持人代操作，成功进入学生工作台 |
| S2 | 学生 | 录入指定数学错题并等待 Mock AI 解析 | 错题保存成功，能找到解析状态与解析结果 |
| S3 | 学生 | 在错题本按科目筛选，打开刚录入的题并修改来源 | 能定位目标题，保存后显示更新内容 |
| S4 | 学生 | 在错题详情生成变式题，完成一次自评练习 | 变式题可见，练习记录成功提交 |
| S5 | 学生 | 查看练习历史、复习计划、周报与消息中心 | 能说明各页面信息含义，并理解复习完成与练习自评是两个动作 |
| T1 | 教师 | 登录后查看教师学情报告并说明数据范围 | 能找到报告，并正确识别为全站聚合而非班级或个人钻取 |
| A1 | 管理员 | 筛选测试用户并查看科目、知识点管理入口 | 能完成查询并识别当前支持的管理边界 |
| A2 | 管理员 | 发布一条带统一测试前缀的公告 | 公告进入列表且学生账号可见；不使用真实通知内容 |

学生任务 S2 使用统一材料：科目“数学”，题干“已知一次函数 y=-2x+3，判断函数随 x 增大如何变化”，正确答案“函数随 x 增大而减小”，来源“体验测试”。管理员公告统一使用标题前缀“[UX-TEST]”；会话结束后通过重置独立测试 schema 清理数据，不触碰开发库。

## 5. 主持流程

1. 建立全新 `wrongbook_ux` schema，运行部署所需 DDL，生成随机数据库账号、JWT 密钥和测试角色密码。
2. 验证后端、前端只监听 `127.0.0.1`，确认开发 MySQL 服务和 3306 端口未被测试流程使用。
3. 向参与者说明目的、数据范围、退出权利并取得口头同意，在记录表中只填写“是/否”。
4. 逐项朗读任务，不解释按钮位置或操作方法；参与者采用“边操作边说”的方式表达困惑。
5. 每项记录完成情况、用时、错误次数、求助次数、1—7 分易用性评分及原话；问题另记入问题表。
6. 会话结束后询问“最困难的一步”“最希望改进的一处”“是否愿意再次使用”，只记录匿名回答。
7. 汇总后按严重级别处理问题；完成修复与回归前，不进入系统冻结或论文效果结论写作。

## 6. 记录口径

- 完成情况：`独立完成`、`协助完成`、`未完成`、`中止`。
- 易用性评分：1 表示“非常困难”，7 表示“非常容易”。
- 错误次数：导致目标偏离、无效提交或需要返回重做的操作次数。
- 求助次数：主持人提供任务提示或操作提示的次数；不得把主持人直接代操作记为完成。
- P0：安全、隐私、越权、数据丢失或污染；立即停止测试。
- P1：核心任务无法完成、服务崩溃或结果严重错误；停止相关任务并优先修复。
- P2：任务可完成但存在明显困惑、反复试错或重要反馈缺失。
- P3：轻微文案、布局或一致性问题，不阻断任务。

原始记录使用 `docs/validation/user-experience-test-record.xlsx`。任务记录和问题记录页均为空白，只在实际会话中由主持人填写；任务目录与字段说明页不属于评价结果。

## 7. 停止条件与完成标准

出现任一 P0、开发数据库连接、真实模型联网、账号凭据暴露或非测试数据写入时，立即停止全部会话，保留最小证据并先处理隔离问题。出现 P1 时停止受影响任务，不继续引导参与者绕过问题。

本轮小规模体验测试满足以下条件后方可结束：

- 计划中的 5 名参与者均完成或明确退出，记录可追溯且无个人敏感信息；
- 学生核心任务 S1—S4 的独立完成率不低于 80%；
- 没有未关闭的 P0/P1，所有 P2 均有明确处理决定；
- 修复后的后端回归、前端 `npm run verify` 和受影响业务联调重新通过；
- 测试数据已从独立环境清理，开发数据库和 Gate5 工件经核对未变化。

上述条件未满足时，只能报告“体验测试尚未完成”及真实问题，不得通过跳过任务、删改记录或降低严重级别制造通过结论。

## 8. 输出与论文使用

实际执行后应形成匿名原始记录、问题清单、修复与回归记录及一段边界清楚的总结。论文仅可描述本次形成性小样本的任务完成情况和可用性问题，不使用“显著提升学习效果”“普遍满意”等超出证据的表述。
